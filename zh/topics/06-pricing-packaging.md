# 定價與 packaging
{: .no_toc }

*約 8 分鐘*

## 為什麼重要

價格是你怎麼發現痛是不是真的。免費用戶可以喜歡你，仍然不重視那件工作。一個價格——即使很小、即使是 pilot 費用——逼出一個你能從中學習的 yes 或 no。Packaging 只是圍著那個價格的提案：他們得到什麼、得不到什麼、以及購買夠小的話，怎麼不用開會就能買。

這是入門，不是定價研究計畫。你不需要 conjoint analysis。你需要一個數字、一個綁在他們替代做法上的理由、以及大聲講出來的膽子。

## 核心概念

- **在你覺得準備好之前就收費。** 準備好是感覺。付費意願是事實。如果 wedge 省下真實的一小時或真實的一美元，就有一個數字。替代做法是否真的讓他們付出代價，見[問題與客戶](../01-problem-customer/)。
- **從價值定價，不是從你的成本。** 軟體毛利高；成本加成會把你推向「便宜」，並吸引不重視那件工作的人。B2B 的粗略價值方程式：替代做法花他們多少（人力、時數、錯誤），你拿掉多少比例，以及你能不能收其中一塊（常被講成三分之一，不是全部）讓他們仍然贏？
- **對消費或學生工具，價值方程式通常是時間和尷尬，不是人數。** 「每個星期天少掉兩小時」是價格錨。「才 $3 所以沒人會想」是你在訓練用戶：你是可有可無的。
- **一個提案，不是一個矩陣。** 早期 packaging 是一個人能說 yes 的單一方案：給誰、得到什麼、價格、期間（月繳、學期、年度 pilot）。Tiers 是不同買家把你往不同方向拉之後才加的。第一天三個 tier 是虛構。
- **免費是帶工作的選擇。** 短、有定義、你需要使用資料的試用——加上結束日期——免費是合理的。永遠免費「為了拿用戶」給你使用量、沒有偏好。如果他們不付、也不介紹會付的人，你學到了。寫下來。
- **刻意把價格往上調。** 第一個數字是探測。如果每個人立刻說 yes，你偏低。對下一個買家往上調，直到你聽到真正的猶豫，然後搞懂為什麼。不要用折扣逃離模糊的 wedge。
- **他們怎麼付，是 packaging 的一部分。** 學生組織可以 Venmo 或刷系上的卡。小公司可以把卡放到 Payment Link。企業 pilot 需要一頁成功標準，不是採購幻想。選你第一個買家這個月真的走得完的路。

## 接下來做什麼

- [ ] 用他們的單位寫價值：省下的時數、避開的錯誤、或現成替代做法的金額。一段話，數字來自真實對話——猜測就標成猜測。
- [ ] 為接下來五個買家選一個價格和一個期間。寫一句提案：「給[誰]，[結果]，每[期間] [價格]。」
- [ ] 接下來三通通話當場講出價格。不要當註腳寄出去。記下他們反應時的原話。
- [ ] 決定什麼*不*包含。寫下來，免得每個 yes 都被客製成另一家公司。
- [ ] 如果公司還沒成立，仍然收一點小錢，或拿到書面承諾（「你能開發票時我們會付 $X」）。握手「之後再付」不是價格測試。
- [ ] 五個真實反應之後再回頭看這個數字，不是看完 Twitter 上一串定價討論之後。把結果接到[指標](../07-metrics-that-matter/)——營收才是指標，不是 waitlist 人數。

## 心智模型

```
  替代做法成本  （他們的數字，不是你的）
        |
        v
  你從那個價值切的一塊  -->  一個價格
        |
        v
  一個 package: 誰 / 結果 / 期間 / 怎麼付
        |
        +--> yes，太快       下次往上調
        +--> yes，帶皺眉     維持，問差點擋住他們的是什麼
        +--> no              是工作、買家、還是價格？
                             不要先假設是價格
```

Packaging 是圍著一個 yes 的盒子。它不是有四欄的定價頁。

## 常見失敗模式

- **等「之後再加定價」。** 之後變成永遠沒有，你有的是帶伺服器的嗜好。第一個價格可以是錯的。零也是一個價格，而且通常是錯的那個。
- **抄公開 SaaS 價格。** 他們的價格反映他們的買家和成熟度。你的第一個買家是你傳訊得到的人。為那個人定價。
- **折扣當信念的替代品。** 「你給回饋我就免費給你」買來客氣的用戶。用折扣換具體的東西（案例、介紹、更長的承諾），或不要折扣。
- **每件事都客製。** 為了成交一個用戶塞進去的每個特別功能都是範圍。見[MVP 範圍](../03-mvp-scope/)。為你現有的 wedge 定價。
